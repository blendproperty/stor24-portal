## Native functionality and optional legacy coverage

STOR24 is the primary forward-looking source. Native unpaid charge detail and sign-in event counts are implemented here. Existing billing previews, rent reviews, settlement CSVs, permission administration, unit notes, maintenance and audit readers are available bounded sources; some need additional consolidated report adapters rather than a new data feed. Other report families need native recording capability: explicit transfer pairs, approved complimentary/deposit classifications, immutable change history, purpose/channel marketing consent, maintained competitor observations, geographic coordinates, or provider passage/call/remittance and endpoint observations. Financial statements additionally need approved accounting definitions and source-to-account/period allocation before useful adapters can be implemented. None of those functionality gaps is solved by inventing historical rows.

The 27 import-backed schemas remain optional ways to display qualified legacy reports. They do not substitute for the native functionality backlog and do not require nonexistent migration records. For a new operation, document the coverage start date and use recorded STOR24 events going forward. If an actual legacy dataset is identified later, apply the provenance and reconciliation controls below.
