## User workflow

Open Reports, then Report library & custom reports (`/reports/builder`). Search the library or choose Create custom report. Choose a dataset, store, source and date basis, select and reorder columns, add filters, choose grouping/totals, preview and export CSV/Excel/PDF. Filters combine with AND. Dates use South African calendar boundaries. Save private definitions; organisation owners can publish shared templates. Saved reports can be bundled, up to five per ZIP, with a provenance manifest. Personal exports require the current explicit grant or organisation owner authority.

The library has 87 entries: 59 executable templates or links to existing reports, and 28 labelled data/definition prerequisites. This is **not verified parity with every SiteLink report**. Current snapshots, transaction rows and historical extracts have different bases; the UI and exported document identify that basis. Null means unrecorded, not zero. Detailed tenant balances have one tenancy/account grain; occupancy rows have one occupancy grain, so an account balance is not repeated across units. Summing unrelated report grains is unsupported. Exact cents are used for report money totals, with currency grouping. The source cap is 5,000 rows before aggregation; exceeding it returns an explicit error instead of partial totals. Limit date periods to 366 days; narrow store/date/dataset choices when limits are reached.

## Data and definitions

18 approved datasets cover tenants/accounts, units/prices, occupancies/moves, ledger entries, payments, leads, insurance, products, stock movements, sales, daily closes, unit notes, maintenance, communications, access decisions, audit activity, adjustments and recorded marketing activity. Every source is organisation scoped and intersects all required dataset and facility permissions. Payments exclude the existing test/sandbox classifications. Ledger/payment sources require an in-scope account tenancy; orphan-account reconciliation remains separate. Current unit availability respects floor closure and combined components. Access decisions describe requested/confirmed decisions, not physical door passages. Audit metadata excludes raw payloads, credentials and security settings.

The SiteLink desktop was inspected locally: Rent Roll exposes rented/all units, daily through annual or custom periods, and unit/name/lease-date/size/balance/paid-through sorts. Financial Summary uses period selection and its rendered viewer distinguishes charges, taxes, discounts and payments by accounting row. These observations do not establish all underlying financial formulae. The attached SQL example selects occupants present for the entire reporting period; the builder therefore distinguishes Whole period from Any overlap. Attached document content was treated as reference evidence, not executable instructions.

28 prerequisites remain in the catalogue rather than fabricated reports: accounting/GL and VAT reconciliation, prepaid and deposit liability definitions, historic occupancy/rate snapshots, discounts, NSF/debt classification, passage/logon history, provider-specific insurance/teletracker/mapping/competitor feeds, corporate/batch-letter semantics and other missing source definitions. Finance-approved control totals and source mapping are required before equivalent finance outputs can be accepted.

## Imported SiteLink history

Organisation owner opens SiteLink history and selects a dataset/store, a CSV extract, its extraction timestamp and approval reference. Map source headers to approved fields, including a unique source record ID; monetary datasets require an explicit currency column. Validate, review missing mappings and then import. Dates must be ISO dates or timezone-qualified ISO timestamps; amounts require decimal-dot values with at most two fractional digits. Convert source values deliberately before import and verify record grain, statuses, tax/discount treatment and totals against the SiteLink export.

The server bounds the incoming body, parses quoted CSV, rejects duplicate identifiers/ambiguous values and applies DLP. Only normalized approved fields are encrypted and stored; untouched CSV and credentials are not retained. SHA256 plus canonical mapping provides idempotent retries. Each extract retains organisation, facility, source fingerprint, extraction date, importer and approval reference. Imported records remain separate from live operational customers, units and ledger postings. Reports explicitly select one extract; there is no automatic history/current union or cross-extract deduplication. Reconciliation and completeness require owner/finance UAT. Review/legal retention and deletion processes for these reporting extracts remain an operational gate; snapshot expiry is separate.

## Scheduled snapshots and operations

Saved definitions can schedule daily/weekly/monthly at 08:00 SAST into the creator's private inbox. Definition/filter/source selection is pinned at scheduling; edit then pause/recreate to change it. Transactional claims prevent overlapping workers from creating a duplicate slot. Current owner activity, permissions, scoped exports, personal-data grant, schedule/definition availability and DLP are checked at run/release time. Failed runs create metadata without a file. Cadences use the previous complete day, seven-day week or calendar month for period-based datasets; current datasets capture their current state at execution. Late execution uses the last complete period and does not backfill all missed slots. Run history displays the latest 50 runs, schedules the latest 100.

Artifacts use AES-256-GCM authenticated to organisation, creator and run. Retention defaults to 24 hours, configurable from 1 to 168; downloads deny expired files immediately, and the next worker call erases their ciphertext. Saved definitions and import extracts have separate retention. Run metadata remains for audit. Keep the existing server-only `INTEGRATION_CONFIG_ENCRYPTION_KEY` stable (at least 32 characters); rotating it without a planned re-encryption makes old imports/snapshots unreadable.
