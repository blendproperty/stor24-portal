## Implemented visibility repair

Netcash operations retains live and test records, adds mode and independently verified method filters for every documented method, labels selected method separately from gateway, and refreshes evidence through TransactionStatus/Check. Reference, trace, amount, ZAR, original merchant/environment and current configuration/source must match. Only method/acceptance observation metadata plus its audit are saved. HMAC-signed, source-bound observation records prevent treating incoming callback Method or forged configuration as verified classification. No Payment, ledger, refund, debit-run, account balance, email or merchant configuration is changed. Bank/card/token/RequestTrace values are not exposed. Generic configuration cannot read/write controlled evidence. Store-scoped booking attribution uses the exact reservation/account/customer relationship; shared-customer association is not sufficient. Public booking payments can be visible before tenancy creation.
