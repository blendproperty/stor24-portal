# Collection email audience preparation

14 October 2026. From Collection email notices, open Prepare multiple notice drafts. Collection-management permission controls both the account list and every selected account. Choose up to20 different accounts, filter by store or search, then preview every recipient, subject and exact message. Search retains hidden selections; changing store clears selection and previous review. Only the explicit selected accounts enter preparation.

Verified email/consent, active tenancy, approved due terms, reconciled overdue amounts and the existing dispute/payment/promise/adjustment holds remain authoritative. Existing approved, cancelled or attempted notices must be handled individually. Confirm that every message was reviewed, then save. All selected drafts and their audits are prepared in one serializable transaction; changed or held sources, scope failures or audit errors roll back the group. Sources and SAST dates are rechecked, records are encrypted, and repeated/overlapping preparation preserves one account/day notice. No automatic retry is added.

After preparation, a different collection manager can select the same audience and preview every saved draft. Independent approval requires every selected notice to be a current DRAFT with matching recipient, subject and message, and the reviewer must not have contributed to any selected draft. Record a review reference and explicitly confirm approval. The server binds every account to its saved notice id/revision, rechecks current consent/source/scope and saves all approvals and per-notice audits in one serializable transaction. A late failure rolls back every earlier approval; repeats and overlapping review cannot replay approvals. No provider transport or communication record is created.

Each saved or approved account link opens the existing individual review and separately confirmed one-attempt email workflow. Group preparation does not approve, and group approval does not send. After approval, preview the audience again. If every notice remains approved/current, the email provider is configured, and the staff member has the existing send grant for each store, a separate explicit confirmation permits sequential group delivery through the existing individual send endpoint. That endpoint rechecks current permission, source, consent, revision and durable attempt claim before each email. No new transport, automatic scheduling or retry is added.

Keep the page open. Delivery is not atomic: an earlier provider-accepted email cannot be rolled back if a later account changes. Failed HTTP/transport, incomplete or mismatched results, SENDING and REVIEW_REQUIRED stop the group. The screen distinguishes accepted/unverified-inbox, in-progress, outcome-needs-review and not-attempted-by-this-group accounts. Navigating away aborts further browser dispatch; a request already received by the server may still finish. Reload individual saved notices after interruption or uncertainty, then explicitly review and confirm only remaining eligible accounts. There is no automatic resume. Provider acceptance never proves inbox receipt. Scheduled escalation, additional channels, separately approved money/access effects and real provider/inbox/staff UAT remain open.

Preview and action failures clear the old review. If saving or approval returns an uncertain or malformed response, reload each saved notice before acting again; the UI does not declare success from an incomplete audience or changed saved message. Selection and successful responses are bounded, private/no-store and management-scoped. This runbook describes source implementation; protected promotion and actual runtime/UAT evidence are recorded separately in PROJECT_CONTEXT.md.
