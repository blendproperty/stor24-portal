# Enquiry and payment comparisons

The native report library includes an enquiry-level comparison and grouped source/payment-outcome counts. Choose a store, enquiry creation period and an end date no later than today in South Africa. Filters include recorded source, consented acquisition source/medium/campaign, self-reported enquiry city/province/postcode, booking conversion and payment outcome. Unknowns and unconverted enquiries remain in the denominator. CSV is an optional report download; it does not submit anything to Netcash or MRI.

One row represents one enquiry. A single original booking may supply its validated initial-rent snapshot, and a converted booking must match the same customer, store, tenancy and account before financial outcomes appear. Multiple bookings, shared account links, altered/missing price snapshots or unreconciled receipts stay review rows. The report does not choose an arbitrary booking or use today's unit price as the original quote. The saved booking quote does not prove signed contractual acceptance. Approved rent-change history remains separately available in Recorded approved rent changes; a joined effective-price timeline is still an outstanding extension of item16.

The source is a single repeatable-read transaction. The existing collections evaluator supplies approved due-date and receipt-proof rules. Net posted receipts reflect effective payment entries less linked refunds and reversals as of the end date. A payment status alone, a card authorisation, test payment, credit/write-off or bank display does not establish receipt. A current account balance is not substituted for as-of arrears. Money totals hold if any financial source requires review. Current holds are labelled separately from historical as-of amounts.

Location comes only from the optional enquiry-origin record; no customer billing address, facility address, IP/GPS or payment-provider referral is inferred. Leading-zero postcodes remain text. Attribution requires retained consented lead evidence. Conflicting/invalid attribution is Unknown with a review reason. Campaign names are current same-store lookup labels, not historical campaign snapshots. This report does not join individual GA visitors, calculate advertising ROI, reconcile GA conversion counts, establish causation, or assess future creditworthiness.

Access intersects reports.financial, reports.sales, leads.view, billing.view and collections.view in the same store. Existing report export, personal-data, saved definition, scheduling and encrypted snapshot controls remain in force. Enquiry/booking references and postcodes are marked personal fields for export. Imported extracts cannot replace this native source. No grants are assigned by this feature.

Safe source bounds are enforced for enquiries, retained attribution, bookings, linked accounts, payment/ledger histories and duplicate-account checks. An exceeded bound produces a narrower-scope request rather than a partial cohort. Missing financial evidence stays missing.

Validation and release evidence belong in PROJECT_CONTEXT.md. Source code, intercepted browser fixtures and isolated PostgreSQL tests do not establish actual marketing/finance acceptance. Original attribution coverage, postcode quality, signed-price/effective-rent history, CRM/GA reconciliation, representative customer/payment history, finance approval, staff training and UAT remain open. No customer/provider operation is part of running this report.
