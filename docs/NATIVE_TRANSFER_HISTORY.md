# Recorded STOR24 transfer pairs

15 October 2026. Open Report library → Units → Recorded STOR24 transfer pairs. This native report uses the explicit `tenancy.transferred` audit written in the same transaction as the operational transfer. Matching move-out and move-in dates never creates a transfer record.

Each retained event supplies its original tenancy, from/to unit and occupancy IDs and effective timestamp. The report verifies those identities against scoped original occupancies, their tenancy/store and recorded source end/destination start dates. Repeated source/destination links, incomplete payloads and inconsistent references/dates stay visible as review rows. The transfer audit reference remains available online and in the configurable column selection. No original event is rewritten or backfilled.

The default period uses **Recorded date (SAST)**, the audit recording timestamp. **Transfer date (SAST)** is a separate basis and can fall in another South African calendar day or period. Default date columns use South African calendar days; exact Recorded timestamp (UTC) and Effective timestamp (UTC) remain available as additional columns. Choosing the effective basis with any candidate event missing a valid effective timestamp is held, rather than silently dropping that event. Use Recorded date (SAST) to inspect its review row. Effective-date selection reads a bounded candidate set; if the source limit is exceeded, narrow to a permitted store or use a recorded-date period. Source sets are limited to5,000 events before totals and never silently truncated.

Unit names and account numbers are current lookup labels; original unit/occupancy/tenancy IDs remain the historical identities. Renaming a unit cannot turn its current label into a historical snapshot. Missing or inconsistent references require review. Counts represent retained audit records, including review rows unless explicitly filtered. They are not verified net new customers, move-outs or financial amounts.

Report and operations grants must intersect for the selected stores. Account, tenancy and occupancy references retain personal-data classification; existing export authorization, DLP, private responses, saved definitions, formats and snapshot rules apply. The optional legacy transfer-history extract remains separate. This does not implement cross-store transfer operations, reconstruct pre-audit history, certify source coverage or prove real staff/finance UAT. The report performs no operational, access or financial mutation. See PROJECT_CONTEXT.md for the distinct testing, commit/push, merge, deployment and production evidence stages.
