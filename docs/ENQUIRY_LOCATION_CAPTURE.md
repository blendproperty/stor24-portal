# Optional enquiry origin

Staff can record city/town, province/region, postal code and country when creating or updating an enquiry. Blank fields are allowed. The Leads screen groups the currently filtered enquiries by retained city, province and postal code; historic/malformed/missing records remain Unknown. Values are customer supplied and unverified, never geocoded or inferred from IP, billing address, facility or advertising source. Postal codes remain text, preserving leading zeros.

`Lead.enquiryLocation` retains version, server-selected capture source and server timestamp. Public general quote intake can submit only the four optional location fields; client source/timestamp/coordinates are rejected. Staff updates use existing scoped permissions, optimistic concurrency, transaction locking and before/after audit. An unchanged value preserves original capture provenance. Clearing all location fields removes the retained origin. No customer billing address is overwritten. Existing public bookings, verification and payment inputs are unchanged.

Rollout status: portal API and staff controls implemented; focused policy, type, lint, schema and responsive browser checks passed locally. Actual PostgreSQL regression execution, protected CI, merge, migration/deployment and signed-in staff acceptance remain required. The public marketing website form, booking location capture and offline/WhatsApp capture are not yet wired; those records remain Unknown. Source quality, duplicate city spelling, historical coverage and representative marketing/payment cohorts remain open. This increment does not close all of Faeez item14 or implement item16.
